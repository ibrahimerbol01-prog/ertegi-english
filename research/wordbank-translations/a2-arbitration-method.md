# Арбитраж спорных переводов A2 (Задание 10) — как сделан

Вход: `a2-arbitration-input.csv` из письма диспетчера, 242 пары. v1 и v2 обезличены, арбитр (Claude, abil-truescope) не автор ни одного варианта. Дата: 06.11.2026.

## Метод (скрипты в `scripts/translation-arbitration/`)

1. `wikt.mjs` — для каждого слова берётся статья английского Wiktionary (MediaWiki API, wikitext). Из таблиц Translations раздела English, **по части речи** (Noun, Verb…), извлекаются переводы на казахский (kk) и русский (ru). Найдено 234 статьи из 236 слов (нет: mp3 player, well-known).
2. `glosbe.mjs` — для kk, если в Wiktionary для этой части речи казахского нет, берётся Glosbe (glosbe.com/en/kk/…). Glosbe **часть речи не различает**, его качество неровное (например, aisle → «Неф»), поэтому он засчитывается только при совпадении с вариантом, не как предложение своего перевода. Страница получена для 180 слов, переводы на казахский — для 140.
3. `arbitrate.mjs` — по каждому языку: вариант совпадает со словарём после нормализации (регистр, ударения, ё→е, пояснения в скобках не учитываются, варианты через «;» «/» «,») → `v1`, `v2` или `both`. Иначе → `human` с причиной в comment (что предлагает словарь). Своих переводов арбитр не подставляет.

## Итог

| | v1 | v2 | both | human |
|---|---:|---:|---:|---:|
| kk | 29 | 31 | 26 | 156 |
| ru | 17 | 18 | 149 | 58 |

Оба языка решены источником в **79** из 242 строк. По правилу `wordbankTranslations.ts` только эти строки станут ai-reviewed; остальные останутся needs-review до решения человека (kk_final/ru_final в a2-review.csv).

Почему так много human по kk: в Wiktionary мало казахских переводов, Glosbe отвечает не на все запросы и не различает части речи. Угадывать по памяти арбитр не стал (правило проекта «не выдумывать»).

Источники в `source_url` — те, по которым принято решение (через пробел, если их два).
