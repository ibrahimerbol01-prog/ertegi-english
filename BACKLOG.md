# BACKLOG: что делать, когда очередь пуста

Правило: не простаивай и не жди диспетчера. Возьми ближайший пункт своей зоны, сделай в своей ветке, отчитайся одной строкой. Новую функцию в приложении без оценки по 4 осям (научная ценность, образовательная ценность, сложность, влияние на исследование) не начинай: сначала оценка в docs/. Исследовательская сборка (study) заморожена, не трогать. Культура и история Казахстана — основа контента.

## Правило пользы
Работа считается сделанной, только если есть ИЗМЕРИМЫЙ результат: PR с цифрами до/после (размер, время, число тестов, ошибки Lighthouse) или документ с решением «взять/не брать» и обоснованием. Нет результата — не начинай. Пример плохого: «посмотрел, всё нормально». Пример хорошего: «LCP 3,4с → 2,1с, чанк −40 КБ, ветка, тесты зелёные».

## Профессионализм сайта (друг; Gemini — анализ, друг — реализация)
1. Lighthouse (Performance, Accessibility, Best Practices, SEO) на главных экранах: таблица оценок, топ-5 проблем, исправить мелкие.
2. Сквозные (E2E) проверки в браузере: вход → сказка → квиз → словарь (Playwright, если ставится; иначе vitest+testing-library). Падающий сценарий = баг-репорт с шагами.
3. Состояния ошибок и пустые экраны: нет сети, пустой словарь, сбой загрузки — понятные тексты kk/ru/en.
4. Единообразие переводов интерфейса: ключи DICT, пропуски перевода, длинные строки на малых экранах.
5. Заголовки безопасности и кэша в vercel.json (CSP, X-Content-Type-Options, Referrer-Policy), без поломки PWA.
6. Оптимизация кода: неиспользуемые зависимости, дубликаты, большие компоненты — разбить, с замером размера.
7. Сверка с конкурентами ПО ФУНКЦИЯМ: взять каталог G11, для каждой 'взять' — мини-спека (экран, данные, тесты, объём в часах) и прототип в ветке за флагом; не включать по умолчанию.

## Плавность и скорость (друг)
Оценка по 4 осям: научная ценность — нет; образовательная — средняя (меньше трения, дольше в занятии); сложность — низкая/средняя; влияние на исследование — ЕСТЬ: любые анимации и ускорения НЕ должны попадать в исследовательскую сборку (VITE_RESEARCH_MODE=1), иначе у групп разный опыт. Делать за alias/флагом или условием на сборку + тест.
1. Анимации только на transform/opacity (без layout), 150-300 мс: переходы между экранами, появление карточек, обратная связь на кнопках, плавная смена слов в карточке. Обязательно уважать prefers-reduced-motion (отключать). Без тяжёлых библиотек (чистый CSS / View Transitions API там, где поддерживается).
2. Скорость: замер до/после (Lighthouse, LCP/INP/CLS, размер начального JS); ленивая загрузка экранов, предзагрузка следующего экрана при наведении/простое, шрифты (subset, display=swap), изображения (AVIF/WebP, размеры), кэш service worker, меньше ререндеров (memo, виртуализация длинных списков словаря).
3. Ощущение скорости: skeleton вместо пустоты, оптимистичные обновления, мгновенный отклик на нажатие (<100 мс).
Результат: PR с цифрами до/после; в отчёте — как проверено, что в исследовательской сборке ничего не изменилось.

## Код и качество (друг, Claude)
1. Дыры в тестах: экраны и данные без проверок; мелкие чини, крупные списком.
2. Производительность и размер чанков: что тянется в начальный JS, что можно ленить.
3. Доступность: клавиатура, контраст, подписи (WCAG 2.1 AA) на экранах словаря и сказок.
4. Подготовка к следующему уровню словаря (A2, B1): скрипт и тесты уже готовы к добавлению файла переводов.
5. Чистка: мёртвый код, дубликаты, устаревшие ветки (списком, не удалять).

## Данные и переводы (Madiii55)
1. Слепые переводы следующих уровней словаря (B1 → B2 → C1) частями по ~300.
2. Ошибки разметки частей речи в списках уровней.
3. Казахские примеры предложений для A1 из наших сказок (только из текста сказок, с номером сказки).

## Исследование и контент (Gemini)
1. Литература: недостающие источники для обзора (только с проверенными ссылками и DOI).
2. Карта региональных и исторических текстов: следующие области/эпохи, источники и права.
3. Абай: шорт-лист и тематическая карта; Шәкәрім, Ыбырай (общественное достояние) по тому же шаблону.
4. Подготовка к апробации: анкеты, инструкция для учителя (на основе docs/research-design, без выдуманных данных), чек-лист согласий.
