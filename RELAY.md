# Почта между Claude

Claude разных аккаунтов не видят друг друга напрямую. Общий репозиторий служит им почтой:
письма и файлы лежат в отдельной ветке `team-relay`, которая в `main` не попадает и код
проекта не трогает. Писать в неё может любой участник с правом Write.

Обычная схема на двоих:

- **Диспетчер** — Claude владельца. Режет работу, пишет задания, проверяет ответы.
- **Исполнитель** — Claude друга. Берёт задание из почты, делает, отвечает с файлами.

Роли можно поменять местами, а участников может быть больше.

## Команды

```
../team.sh send ЛОГИН "Заголовок" "текст"|файл.md [файлы...]   отправить письмо
../team.sh inbox                     новые письма мне (с текстом и путями к файлам)
../team.sh inbox --wait=15           ждать новое письмо до 15 минут
../team.sh inbox --all               все письма мне со статусами
../team.sh read ID                   показать письмо
../team.sh get ID папка              скопировать файлы письма в папку
../team.sh reply ID "текст" [файлы...]   ответить; письмо станет done
../team.sh done ID                   отметить прочитанным без ответа
```

Нужны `git`, доступ Write к репозиторию и `gh auth login`. Без `gh` логин можно задать
вручную: `TEAM_LOGIN=мой-логин ../team.sh inbox`.

## Как писать задание (диспетчеру)

Одно письмо — одна задача, которую исполнитель сделает за одну сессию. В письме:

1. **Цель** — что должно получиться.
2. **Входные файлы** — приложены к письму или лежат в репозитории (путь).
3. **Как сделать** — шаги, если они важны; иначе оставь выбор исполнителю.
4. **Что вернуть** — файлы, ветку или PR, короткий отчёт.
5. **Готово, когда** — проверяемые условия.

Если результат — код в проекте, исполнитель сдаёт его обычным путём (задача → ветка → PR),
а в ответе на письмо даёт ссылку на PR. Файлы через почту — для черновиков, данных,
текстов, картинок и всего, что не идёт в `main` сразу.

## Старт-промпт для исполнителя (Claude друга)

```
Ты исполнитель в паре Claude. Мой GitHub — <логин>. Прочитай README.md и RELAY.md в ветке team-relay (git fetch origin team-relay && git show FETCH_HEAD:RELAY.md).
Цикл: ../team.sh inbox --wait=15 → если есть письмо, прочитай его и приложенные файлы,
кратко скажи мне план и выполни → ответь через ../team.sh reply ID "отчёт" [файлы]
→ снова inbox --wait=15. Если задание неясно — ответь вопросом через reply, не угадывай.
Код в проект сдавай через ../team.sh start/pr, в ответе дай ссылку на PR.
Ключи, пароли и .env не пересылай и не читай.
```

## Старт-промпт для диспетчера (Claude владельца)

```
Ты диспетчер в паре Claude, исполнитель — @<логин друга>. Прочитай RELAY.md в ветке team-relay.
Цель на сессию: <…>. Разбей её на задания на одну сессию каждое, покажи мне список,
после «ок» отправляй по одному через ../team.sh send. Жди ответ (inbox --wait=15),
проверяй результат по «готово, когда», при проблемах отправляй уточнение, иначе следующее
задание.
```

## Правила

- Ключи, токены и файлы `.env*` через почту не пересылаются (скрипт их не примет).
- Не сливать `team-relay` в `main` и не открывать из неё PR.
- Большие файлы (больше 20 МБ) через почту не гонять: GitHub отклонит файлы больше 100 МБ.
  Положите их в облако и пришлите ссылку.
- Почта видна всем, у кого есть доступ к репозиторию.
