# T-L2: код для соответствия чек-листу 20 пунктов

Задача T-L2 → Магжан. Соответствие сайта чек-листу из 20 пунктов (приложено владельцем), суть и дизайн сайта не менять.
Зачем: продукт и стартап: сайт не должен получить претензий (доступность, согласия, данные детей, удаление данных). Юридические тексты пишет Gemini (T-L1), ты делаешь код.
Что сделать, по порядку, каждый пункт отдельным маленьким PR от main (ветки fix/a11y-..., feat/legal-links-...), PR не мержить:
1. Доступность (пункты 13, 14, 15): найди элементы div/span с onClick без роли и клавиатуры (в src их около 6) и замени на button либо добавь role, tabIndex, обработку Enter/Space; проверь видимый фокус; проверь контраст пар цветов дизайн-системы (docs/design-system.md, нужно 4.5:1 для текста, 3:1 для крупного/элементов) и исправь только провалы минимально; alt у всех img уже есть, проверь осмысленность и декоративные с alt="". Добавь тесты.
2. Согласия в формах (пункты 6, 7, 17): проверь AuthScreen: галочка политики не отмечена заранее, текст ссылки читается, согласия не склеены, запрашиваются только нужные поля (минимум данных); опиши отчётом, что собираем и зачем (сверь с docs/privacy/data-inventory.md). Возрастное согласие для детей: когда Gemini пришлёт parental-consent, сделай тексту место в регистрации (кнопка/строка «мне меньше N лет: нужно согласие родителя»), N возьми из его ответа с источником, не придумывай.
3. Ссылки на документы (пункты 1, 2, 3, 4, 16): внизу экрана входа и в профиле/настройках ссылки «Политика конфиденциальности», «Соглашение», «Возврат», «О хранении данных», «Контакты» (тексты придут от Gemini; сначала подготовь компонент и пустые страницы-заглушки kk/ru/en за существующей схемой PrivacyPolicy.tsx, строки через dict.ts, тест на паритет должен пройти).
4. Удаление данных (пункт 20): проверь, что DeleteAccount доступен из профиля в 2 касания, виден ученику и учителю, на экране написано, что удаляется и что остаётся; добавь ссылку на процедуру.
5. Тёмные паттерны и скрытые платежи (9, 10): просмотри экраны на предмет скрытых отказов, давления, фальшивой срочности, предвыбранных платных опций; сейчас платежей нет, проверь только это и напиши список «чисто / замечания».
6. Сторонние SDK и cookie (5, 8): подтверди список сторонних вызовов из кода (Supabase, Azure Speech, Gemini через api/*) и что трекеров нет; баннер cookie не добавляй, пока Gemini не ответит, нужен ли он (storage-cookie-notice).
Не делать: не менять API, миграции, vercel.json, зависимости, research-сборку (VITE_RESEARCH_MODE=1 должна оставаться без новых экранов), платёжный код, внешний вид кроме исправлений контраста и фокуса.
Как проверить: npm run lint, npm test, npm run build зелёные; в каждом PR список файлов и как проверить руками.
Риск: R1 (только PR на ревью, мерж делает владелец после питча).
Порядок и лимиты: сначала T-M2 и T-M3 (если не готовы), затем 1, 4, 3, 2, 5, 6. Если лимит Claude кончается, напиши, что сделано, и остановись.
