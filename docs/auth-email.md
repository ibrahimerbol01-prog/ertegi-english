# Вход по почте и сброс пароля: настройка Supabase

Дата: 05.11.2026. Код: `src/AuthScreen.tsx` (регистрация, «Құпиясөзді ұмыттың ба?»), `src/components/SetPassword.tsx` (новый пароль по ссылке из письма), `src/App.tsx` (событие `PASSWORD_RECOVERY`).

## Что делает приложение

- **Регистрация по почте:** `signUp` с `emailRedirectTo = адрес сайта`, на котором ученик (у исследования свой адрес). Письмо с подтверждением уходит, если в Supabase включено «Confirm email».
- **Сброс пароля:** кнопка «Құпиясөзді ұмыттың ба?» → `resetPasswordForEmail`. Ответ всегда один и тот же, есть аккаунт или нет, чтобы нельзя было проверять, кто зарегистрирован. Ссылка из письма открывает сайт, Supabase входит по ней временной сессией, приложение показывает экран «Жаңа құпиясөз» до всего остального.

## Что нужно настроить в Supabase (код этого не делает)

Письма реально приходят только при **своём почтовом сервере (SMTP)**. Встроенная отправка Supabase рассчитана на пробу: у неё очень малый лимит писем в час и она отправляет только адресам членов команды проекта (условия проверь в документации Supabase: они меняются). Для учеников это не подходит.

1. **Authentication → Sign In / Providers → Email:** «Confirm email» включено.
2. **Project Settings → Authentication → SMTP Settings:** включить «Custom SMTP» и ввести данные сервиса рассылки (Brevo, Resend, Mailgun и т. п.; условия бесплатных тарифов и требования к домену отправителя проверить у самого сервиса). Адрес отправителя должен быть подтверждён у сервиса; письма с чужого домена без настройки SPF/DKIM попадают в спам.
3. **Authentication → URL Configuration:** в **Redirect URLs** оба адреса: `https://ertegi-english.vercel.app` и `https://ertegi-study.vercel.app` (и `https://ertegi-study.vercel.app/**`, если нужен путь). **Site URL** оставить основным сайтом.
4. **Authentication → Email Templates** (по желанию): тексты «Confirm signup» и «Reset password» на казахском; ссылку `{{ .ConfirmationURL }}` не менять.
5. **Проверка:** зарегистрироваться на **своей** почте, дойти до письма; потом «Забыли пароль» → письмо → новый пароль → войти. Проверить папку «Спам».

## Решения для исследования

- В исследовании учебный аккаунт ученика привязан к почте: это персональные данные ребёнка. В этическом пакете (0.2, п. 3) предложено только e-mail без Google, а вопрос о хранении данных за рубежом ещё не решён. Подумать, нужны ли ученикам отдельные адреса (например, школьные) и что писать в согласии.
- Сброс пароля нужен исследованию напрямую: потеряв пароль, ученик потеряет код участника на устройстве и выпадет из отсроченного теста; но код хранится в `learner_state`, поэтому после входа на новом устройстве он вернётся.
