# Конвейер данных исследования

Дата: 05.11.2026. Скрипт `scripts/study-dataset.py` превращает выгрузку `learning_events` в таблицы под модель из `study-design.md`, 3.2. Он ничего не придумывает: только пересобирает то, что приложение записало.

## Шаги

1. В Supabase SQL Editor выгрузить события исследования в CSV:
   `select user_id, verb, object_type, object_id, story_id, level, result, context, occurred_at from learning_events where context->>'research' = 'true' and context->>'study_id' = 'ertegi-stage0-2027';`
2. Положить рядом `allocation.csv` (выход `scripts/study-codes.mjs`) и `assignment.csv` (`code,story_id,condition[,position]`, F = фольклор, C = контроль; план рандомизации, приложение его не пишет).
3. `python3 -I scripts/study-dataset.py --events events.csv --assignment assignment.csv --allocation allocation.csv --study-id ertegi-stage0-2027 --content-versions <даты через запятую> --out out/`
4. Проверка самого скрипта: `python3 -I scripts/study-dataset.py --selftest` (синтетика, только для проверки; эти числа нигде не использовать).

Выгрузки с кодами и таблица «код → ученик» хранятся только у ответственного исследователя, не в репозитории (`research-evidence.md`, 9.2).

## Кодбук

**words.csv**, строка = ученик × целевое слово (формат «значение» — основная мера H1).

| Поле | Смысл |
|---|---|
| `code` | код участника ERT-NNNC |
| `story_id`, `word` | сказка (пара текстов) и слово |
| `folk` | 1 = слово читали в версии F, 0 = в C; пусто, если ученика нет в `assignment.csv` |
| `known_pre`/`known_post`/`known_delayed` | 1 верно, 0 неверно или «Білмеймін»; пусто = пункт не отвечен (в основном анализе пропуск) |
| `form_pre`, `form_delayed` | форма теста A/B |
| `position` | из `assignment.csv`, иначе порядок первого `story_open` (наблюдаемый) |
| `taps` | нажатий на слово в тексте (механизм, в модель H1 не входит: это переменная после воздействия) |
| `itt`, `per_protocol`, `early_exposure`, `version_ok` | флаги выборки, копия из students.csv |

**students.csv**: завершённые сессии, `tales_completed`, `conditions_completed`, ITT (есть претест и отсроченный тест), per-protocol (ITT + ≥ 4 текстов + оба условия), `early_exposure` (сказка исследования открыта до конца претеста), `content_versions`, `version_ok`.

**consort.csv**: счётчики для схемы движения участников.

## Что делает с данными

- Берёт только события со `research: true` и нужным `study_id`; пункты-образцы (`sample`) отбрасывает.
- Код участника приписывает всем событиям пользователя; пользователь с двумя разными кодами исключается и считается отдельной строкой CONSORT.
- Повтор одного пункта на одном срезе (повторная отправка из очереди) берётся первым.
- Псевдослова из основной меры исключены.

## Ограничения

- Метрики по форматам «узнавание», «использование», «понимание» (чувствительный анализ б) скрипт пока не собирает; основной анализ идёт по «значению».
- Знакомость сюжета и трудность текста (проверка манипуляции, 3.4) и опрос мотивации в приложении не сделаны, значит и в таблицах их нет.
- Модель `glmer` (3.2) здесь не запускалась: R в контейнере нет. Скрипт анализа будет написан и проверен на синтетике в среде с R до предрегистрации.
