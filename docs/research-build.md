## Как собрать второй проект Vercel

1. Тег кода: `git tag study-2027-v1 <коммит> && git push origin study-2027-v1`. Исследование идёт на теге, а не на `main`.
2. Vercel → Add New Project → тот же репозиторий, имя например `ertegi-study`. Production Branch: отдельная ветка `study` (создаётся из тега: `git branch study study-2027-v1 && git push origin study`), чтобы слияния в `main` не попадали на сайт исследования.
3. Environment Variables (Production):
   - `VITE_RESEARCH_MODE=1`;
   - `VITE_STUDY_ID=ertegi-stage0-2027` (свой id на этап 0 и этап 1, он пишется в каждое событие);
   - `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` (проверка входа в `/api/*`), `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION` (озвучка нейронным голосом) — как на основном проекте;
   - **не задавать** `GEMINI_API_KEY` и `ANTHROPIC_API_KEY`: тогда `/api/shoqan` не работает и на сервере, даже если кто-то вызовет его вручную.
4. Supabase: применить миграцию `supabase/migrations/20261109000000_study_code.sql` (SQL Editor) до первого входа ученика. Без неё код участника остаётся только на устройстве, а ответы теста сервер не принимает и они ждут в очереди на устройстве (до 500 событий).
5. Supabase Auth → URL Configuration: добавить адрес нового сайта в Redirect URLs (вход через Google).
6. Проверка после выкладки: вход тестовым учеником, ввод кода, 5 сказок в библиотеке, нет Шоқана, вкладка «Тест» с плашкой «ҮЛГІ» (пока стоит образец), в `learning_events` у новых строк `context->>'research' = 'true'` и нужный `study_id`.

## Коды участников

Формат `ERT-NNNC`: три цифры и контрольная цифра Damm. Опечатка в одной цифре и перестановка двух соседних цифр не дают чужой код: экран просит проверить код. Ученик вводит код один раз после обычного входа; принимаются `ERT-5724`, `ert 5724`, `5724`, `ЕРТ-5724` (кириллица).

Выдача кодов:

```
node scripts/study-codes.mjs 40 > allocation-stage0.csv
```

Файл `code,sequence`: уникальные случайные коды, ровно половина с последовательностью форм AB, половина BA, в случайном порядке. Этот файл — ключ соответствия: он хранится только у ответственного исследователя, не в репозитории и не у учителя (`research-evidence.md`, 9.2). Учитель получает карточки с кодами без последовательности; кто какой код получил, записывает исследователь в отдельном ключе «код → ученик».

Последовательность форм определяется числом в коде (**предложение на утверждение**): чётное NNN — A (претест) → B (немедленный) → A (отсроченный), нечётное — B → A → B (`study-design.md`, 5.3).

Где хранится код: `localStorage` `ertegi_study_code_<user_id>` и `learner_state` (`kind = 'study_code'`, `key = 'code'`, значение `{ code, at }`), поэтому код переходит на другое устройство. Сервер принимает только код вида `ERT-NNNN`. Удаление аккаунта удаляет код вместе с остальным.

## Тест R5

Экран `src/research/test/TestScreen.tsx`, вкладка «Тест». Ученик выбирает сессию, которую называет учитель: «Алдын ала тест» (pre), «Кейінгі тест» (post), «Кешіктірілген тест» (delayed). Форма берётся из кода участника и не меняется после начала сессии. Законченная сессия закрыта.

- Без XP, без подсказок, без таймера, без перевода по нажатию, без «верно/неверно» после ответа и без итогового балла на экране; назад вернуться нельзя.
- Каждый ответ сразу пишется в `localStorage` (`ertegi_research_test_<user_id>`), потом в журнал (`test_answer`). При обрыве сети журнал ждёт в очереди и уходит позже; после перезагрузки страницы тест продолжается с первого неотвеченного пункта. Конец сессии — событие `test_complete` со сводкой по форматам (`docs/events.md`).
- Время ответа на пункт пишется (`duration_ms`, до 30 мин), но на экране не показывается.

### Формат набора пунктов

JSON, проверяется при загрузке (`validateTestSet` в `src/research/test/engine.ts`):

```json
{
  "version": "stage0-v1",
  "sample": false,
  "items": [
    { "id": "A-mean-07", "word": "loyal", "format": "meaning", "prompt": null,
      "options": ["адал", "ашулы", "сабырлы", "батыл"], "answer": "адал", "dont_know": true,
      "form": "A", "timepoints": ["pre", "post", "delayed"], "story_id": "alpamys" }
  ]
}
```

- `format`: `recognition` (варианты строго `["yes", "no"]`, ответ `no` только у псевдослова с `"pseudo": true`), `meaning` (обычно с `"dont_know": true`, «Білмеймін» засчитывается как 0), `use` (`prompt` — предложение с `___`), `comprehension` (`prompt` — вопрос, `word` пустой).
- Порядок пунктов и вариантов в сессии — порядок в файле: он часть формы.
- `version` меняется при каждой правке пунктов; прогресс на устройстве хранится отдельно по версии, поэтому образец не закрывает настоящие сессии.

### Как загрузить утверждённые пункты

1. Руководитель утверждает пункты (слова: `study-design.md`, 5.2; формы: 5.3).
2. Положить файл в `src/data/researchTest.json` (рядом с образцом). Если он есть, сборка берёт его вместо `researchTest.sample.json` без правки кода.
3. `npm test` (проверка формата) и `VITE_RESEARCH_MODE=1 npm run build`.
4. Коммит в ветку `study` до заморозки, новый тег.

Сейчас в репозитории только **образец** `src/data/researchTest.sample.json`: 7 пунктов с префиксом `SAMPLE`, `"sample": true`. Экран показывает плашку «ҮЛГІ: бұл нағыз тест емес», события образца помечены `sample: true`.
