## 6. Замеченные проблемы скорости

1. **`supabase-*.js` (54,5 КиБ gzip) в критическом пути**, хотя на заставке он не нужен для отрисовки: Lighthouse оценивает неиспользуемый код в нём в ~83 % (~45 КиБ). Варианты: загружать клиент Supabase динамически (`import()`) после первой отрисовки, или вынести `getSession` в отложенный эффект.
2. **Entry-чанк `index-*.js` 81 КиБ gzip** (React + App + AuthScreen + IntroScreen + RolePicker + орнаменты); ~56 % кода не исполняется на первом экране. `AuthScreen` и `RoleScreen` можно сделать ленивыми, показывая сначала только заставку.
3. **`KazakhTalesApp-*.js` — самый крупный прикладной чанк (334 КБ сырых / 110 КиБ gzip)**: в нём `constants.ts` (≈128 КБ исходника — сказки/словарь), Council, LegendCards, WeekWords, ThinkingTrail, Culture и др. Предзагрузка в простое добавляет на слабой сети ~110 КиБ и long task при разборе. Стоит вынести данные сказок в отдельные чанки/JSON по уровням и сделать ленивыми редкие экраны (Legend, Council, WeekWords, Culture).
4. **CSS 72 КБ (12,7 КиБ gzip) блокирует отрисовку** — Lighthouse оценивает экономию ~150 мс. Можно проверить объём неиспользуемых классов Tailwind / вынести критический CSS заставки.
5. **Google Fonts** подключены блокирующим `<link rel="stylesheet">` с внешнего домена (два семейства, 7 начертаний). На реальной мобильной сети это дополнительные DNS/TLS и задержка отрисовки текста. Варианты: самостоятельный хостинг шрифтов (woff2, subset кириллица+латиница), `preload` основного начертания, сокращение числа начертаний.
6. **Long tasks при старте** до 200–370 мс при CPU ×4 (основной вклад — исполнение entry-чанка и разбор предзагружаемого `KazakhTalesApp`). Предзагрузку стоит запускать после взаимодействия пользователя или разбивать.
7. Speech SDK (369 КБ) уже ленивый и исключён из precache — замечаний нет.
8. Прочее (не скорость): `npm audit` — 12 уязвимостей зависимостей (2 high), стоит разобрать отдельно; 2 предупреждения oxlint.
