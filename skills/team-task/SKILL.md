# Работа над задачей в команде

Проект общий для нескольких людей, у каждого свой Claude. Твоя цель — довести одну задачу
до PR, не мешая остальным. Правила команды в `CLAUDE.md` важнее этого навыка.

## 0. Контекст (один раз за сессию)

- Прочитай `.github/team.conf` и раздел своей роли в `docs/team/ROLES.md`.
- Не знаешь роль человека — спроси. Не знаешь его логин — `gh api user --jq .login`.
- `scripts/team.sh doctor`; если что-то красное, сначала помоги починить.

## 1. Взять задачу

- Есть номер: `scripts/team.sh start <номер>`, затем `gh issue view <номер> --comments`.
- Нет номера: `scripts/team.sh board`, предложи 1–2 задачи со `status:ready` своей роли.
- Нет подходящей задачи, но человек просит работу: создай её
  (`scripts/team.sh task "Название" <роль>`), а не работай без задачи.
- Если в комментариях есть «Передача», начни с неё.

## 2. План

Перед правками покажи план из 3–6 шагов: какие файлы, что проверишь. Жди «ок».
Если план выходит за свою зону или задевает файлы `shared` (зависимости, lock-файл,
миграции, общие настройки) — скажи об этом прямо и предложи отдельную задачу.

## 3. Работа

- Только в ветке задачи. Проверь `git rev-parse --abbrev-ref HEAD` перед первым коммитом.
- Коммиты маленькие: `тип: суть (#номер)`, типы `feat fix docs test chore refactor`.
- Ключи и токены никогда не пиши в файлы. Нужна новая переменная — имя в `.env.example`,
  значение человек возьмёт у владельца.
- Экономь контекст: grep вместо чтения папок, не пересказывай код.
- Застрял больше чем на 20 минут или ждёшь другую роль — повесь `status:blocked`
  (`gh issue edit <номер> --add-label status:blocked`) и напиши в задаче, чего ждёшь.

## 4. PR

1. Пройди по «Готово, когда» в задаче, отметь что выполнено.
2. `scripts/team.sh sync`. Конфликт — реши, если он в твоём коде; в чужом — спроси человека.
3. `scripts/team.sh pr` (сам запустит проверки из `CHECK_CMD`).
4. Заполни в PR «Что сделано» и «Как проверить» (`gh pr edit --body-file`), отметь чек-лист.
5. Не сливай. Скажи человеку ссылку на PR и что слияние за владельцем.

## 5. Конец сессии без готового PR

Закоммить и запушь, затем `scripts/team.sh note <номер> "…"`: что сделано, что осталось,
где проблема, какие файлы трогали. Одна-три строки на пункт.

## Задание пришло письмом

Если человек говорит «проверь почту» или работает исполнителем в паре
(`docs/team/RELAY.md`): `scripts/team.sh inbox` (или `--wait=15`), прочитай письмо и файлы
по указанному пути, скажи план, выполни. Ответ с отчётом и файлами —
`scripts/team.sh reply ID "…" [файлы]`; для кода в проекте — ссылка на PR.

## Никогда

Пушить в `main`, сливать PR, `--force` без `--with-lease`, править чужую ветку без просьбы
её автора, читать или выводить содержимое `.env*`.
